# AGENTS.md — инструкция для ИИ-агентов (Codex, Copilot, Gemini и др.)

## Что это
DJIGIT TAU CRM — CRM студии кавказского танца (Казахстан, ₸). Интерфейс на русском.
- ТЗ: `docs/MASTER_PROMPT.md` — читать первым.
- Архитектура, правила, выполненные этапы и **где остановились**: `docs/ARCHITECTURE.md` (раздел «План» и строка «Где остановились»).
- Запуск и публикация: `README.md`.

## Стек и структура
- `app/` — React + TypeScript + Vite. Страницы в `app/src/pages/`, общие модули в `app/src/lib/`:
  `supabase.ts` (клиент, роли, `errText`), `auth.tsx` (`useAuth`, `useMe`), `ui.tsx` (`useLoad`, `must`, `act`, `toast`, `Modal`, `Field`, форматирование, `TZ`), `refs.ts` (справочники).
- Меню и доступ к страницам по ролям — `MENU` в `app/src/Layout.tsx`; маршруты — `PAGES` в `app/src/App.tsx`.
- `supabase/migrations/NNNN_*.sql` — схема, RLS, триггеры, RPC. Нумерация последовательная.
- `supabase/functions/` — Edge Functions (`admin-users` — аккаунты, только директор).
- Корень (`index.html`, `assets/`) — собранный сайт для GitHub Pages. Руками не править: `cd app && npm run publish`.

## Правила
1. Права проверяет база (RLS + функции `private.*` из `0002_security_rls.sql`). Новая таблица — сразу `enable row level security` и политики. Скрытие кнопок — только удобство.
2. Секреты (service role key, ключи amoCRM) — только в Supabase → Edge Functions → Secrets. В репозиторий и во frontend — никогда. В `app/.env.*` только публичные URL и publishable-ключ.
3. Никаких выдуманных данных и демо-цифр. Все таблицы читают из базы, все расчёты по реальным записям.
4. Важные операции не удаляются (платежи, выплаты) — только отмена или возврат. Изменения пишутся в `audit_logs` триггером `private.audit`.
5. Время студии — `Asia/Almaty` (`TZ` в `ui.tsx`, `private.tz()` в базе).
6. Роли: director, manager, admin, sales, trainer. Управляющий видит только назначенные филиалы (`employee_branches`).
7. Каждая кнопка работает; нет недоделанных разделов в меню — пункт добавляется, когда страница готова.
8. Не удалять данные в базе без согласования с заказчиком.

## Как работать
1. Прочитать `docs/ARCHITECTURE.md`, взять следующий невыполненный этап.
2. Изменения базы — новой миграцией `supabase/migrations/NNNN_*.sql`, применить к проекту Supabase (нужен доступ к проекту; если доступа нет — оставить миграцию и написать заказчику применить её в Supabase → SQL Editor).
3. Код: следовать стилю существующих страниц (`useLoad` + `must`, `act` для действий, `Modal`/`Field` для форм).
4. Проверка: `cd app && npm run build` (типы + сборка). Затем проверить в браузере под разными ролями. Тестовые данные после проверки удалить.
5. Обновить `docs/ARCHITECTURE.md`: отметить этап `[x]`, описать сделанное, обновить «Где остановились».
6. Опубликовать: `cd app && npm run publish`, закоммитить, отправить в `main`.
