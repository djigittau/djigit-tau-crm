## 3. Архитектура

Принцип ТЗ: «используй существующий стек, не переписывай без необходимости».

```
Браузер (index.html, ванильный JS)  ──  supabase-js  ──>  Supabase
  - интерфейс и роли                                      - PostgreSQL + RLS (права на уровне базы)
  - слой данных data.js:                                  - Auth (email/телефон + пароль, bcrypt)
    load / save / remove по таблицам                      - Storage (фото тренеров)
                                                          - RPC: продажа, возврат, отчёты, ЗП
```

- **React не нужен.** Интерфейс уже работает. Переписывание на React — это месяцы работы и риск сломать рабочее. Меняем только слой хранения: вместо localStorage — запросы в Supabase.
- **Права доступа проверяет база (RLS)**, а не интерфейс. Даже если тренер откроет консоль браузера, он не получит финансы — база их просто не отдаст.
- **Вход:** Supabase Auth с паролями в bcrypt. Вход по телефону: телефон превращается во внутренний логин `77011234567@phone.djigit` — без платных SMS. Email работает напрямую.
- **Переход по модулям:** каждый раздел переключаем на базу отдельно и проверяем тестами. В любой момент CRM остаётся рабочей.

**Деньги без двойного учёта скидок:** в продаже хранится `list_price` (полная цена), `discount` (скидка) и `price = list_price − discount` (к оплате). Выручка считается по фактическим оплатам в `transactions`, скидка — отдельный показатель, возврат — отдельная транзакция-расход категории «Возврат» плюс запись в `refunds`.

## 7. Решения, нужные от руководителя

1. **Где хранить данные.** Supabase сейчас во Франкфурте. Закон РК о персональных данных требует хранить данные граждан РК в Казахстане. Для своей студии риск ниже, для продажи CRM другим — критичен. Варианты: оставить Supabase / развернуть Supabase на казахстанском сервере (PS Cloud, Kazteleport).
2. **Реальные данные.** Откуда перенести учеников, оплаты и сотрудников: из Google-таблицы «Камран_УО» (импорт уже есть) или вводить заново.
3. **Права «по разрешению»**: кому из администраторов давать возвраты, скидки и финансы.
4. **Тарифы и цены** по категориям — заполните сами в разделе «Категории» после этапа 3.

## 8. Риски

- Переход на базу — самая большая и рискованная часть. Поэтому по модулям и с тестами.
- Пока не сделан этап 8, вход в CRM остаётся демо-защитой. **Реальные данные учеников вносить только после этапа 8.**
- Объём: этапы 2–10 — это несколько больших заходов работы, не один.
