## Архитектура

```
Браузер (React + TypeScript, Vite)
  │  supabase-js: только публичный anon-ключ
  ▼
Supabase
  ├─ Auth — вход по email/телефону и паролю
  ├─ PostgreSQL — все данные; RLS проверяет роль и филиал в каждом запросе
  ├─ RPC (security definer, с проверкой прав): смены, зарплата, расписание, профиль
  └─ Edge Functions (service role, секреты в env):
       • admin-users — директор создаёт и блокирует аккаунты
       • amocrm-oauth, amocrm-webhook, amocrm-sync — интеграция amoCRM → CRM
```

Секреты (service role, OAuth secret, токены amoCRM) — только в переменных Edge Functions и в `private.amocrm_credentials`. Схема `private` не доступна через API.

### Роли и доступ (проверяется в базе, см. `0002_security_rls.sql`)

| Роль | Видит | Меняет |
|---|---|---|
| Директор | всё | всё; только он создаёт аккаунты, меняет роли, филиалы, настройки, amoCRM |
| Управляющий | назначенные филиалы | как администратор + утверждает зарплаты, бонусы, корректировки |
| Администратор | свой филиал | пробники, ученики, группы, расписание, аренда, коммунальные, расходы, страховка, черновики зарплат, штрафы |
| Отдел продаж | пробники, родители, ученики своего филиала; свои продажи | пробники, продажи, платежи |
| Тренер | свои группы, их учеников, свои смены, свои начисления | посещаемость своих занятий |

Заблокированный сотрудник не видит ничего: все проверки требуют `status = 'active'`.

### Правила целостности

- Родитель уникален по нормализованному телефону (`8 701…` = `+7 701…`). Повторная заявка привязывается к тому же родителю.
- Одна отметка посещаемости на ученика на занятии. Отменённое занятие отметок не принимает.
- Одна открытая смена на сотрудника. Ручная правка времени записывает автора.
- Зарплата = оклад (по филиалу) + занятия `scheduled`/`completed` × единая ставка (`crm_settings.lesson_rate`) + бонусы − штрафы. Посещаемость не влияет. Утверждённое начисление меняет только директор.
- Продажа хранит отдельно цену, скидку и сумму к оплате. Деньги — в `payments`; удалять платежи нельзя, только возврат.
- Платежи, выплаты и webhook-события защищены уникальным ключом от повторов.
- Каждое изменение важных таблиц пишется в `audit_logs` триггером: кто, роль, старые и новые значения, филиал, IP. Изменять и удалять журнал не может никто.

## Этап 2. База данных — выполнено

Миграции в `supabase/migrations/`, применены к проекту:

1. `0001_core_schema.sql` — типы и 31 таблица со связями, ограничениями и индексами.
2. `0002_security_rls.sql` — функции проверки прав и RLS-политики на всех таблицах.
3. `0003_triggers_functions.sql` — журнал, триггеры целостности, RPC, справочники (7 статей расходов, часовой пояс Asia/Almaty, валюта KZT, ставка за занятие 0).

Проверка прав (тестовые данные в транзакции с откатом): управляющий другого филиала не видит чужих учеников и зарплат; администратор не повышает себе роль и не утверждает зарплату; продажи не видят расходы и не создают пробник в чужом филиале; тренер видит только свою группу, не видит продажи, платежи и журнал, не отмечает чужую группу; второй раз смену не открыть; дубль родителя не создаётся; последнего директора не снять; заблокированный не видит ничего.

## Этапы 3–4. Вход, роли, филиалы, сотрудники — выполнено

- Приложение `app/` (React + TypeScript + Vite), тёмная тема с золотом, боковое меню (сворачивается, на телефоне выезжает).
- Вход по email или телефону. Сотрудник без email получает служебный логин `7XXXXXXXXXX@phone.djigittau.kz` — он вводит просто телефон.
- Временный пароль → обязательная смена при первом входе (`user_metadata.must_change`).
- Меню и маршруты по роли; данные дополнительно защищены RLS.
- Страницы: Главная (директор, управляющий), Профиль, Смена, Филиалы, Сотрудники, Настройки (ставка за занятие).
- Edge Function `admin-users`: создать, изменить, заблокировать/деактивировать (вместе с запретом входа в Auth), сбросить пароль. Проверяет, что вызывает активный директор; действия пишутся в журнал.
- Первый директор `director@djigittau.kz` создан SQL-скриптом с временным паролем.

Проверено в браузере на настоящей базе (19 проверок): вход и ошибка пароля, смена временного пароля, меню каждой роли, создание филиала и сотрудников, отказ на дубль телефона, назначение управляющего, вход тренера по телефону, начало и конец смены, отказ второй смены через API, тренер не может сменить роль и создать аккаунт через API, тренер видит только свой филиал, управляющий не создаёт аккаунты, заблокированный не входит. Тестовые данные удалены.
