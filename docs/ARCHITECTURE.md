## Архитектура

```
Браузер (React + TypeScript, Vite)
  │  supabase-js: только публичный anon-ключ
  ▼
Supabase
  ├─ Auth — вход по email/телефону и паролю
  ├─ PostgreSQL — все данные; RLS проверяет роль и филиал в каждом запросе
  ├─ RPC (security definer, с проверкой прав): смены, зарплата, расписание, профиль
  └─ Edge Functions (service role, секреты в env):
       • admin-users — директор создаёт и блокирует аккаунты
       • amocrm-oauth, amocrm-webhook, amocrm-sync — интеграция amoCRM → CRM
```

Секреты (service role, OAuth secret, токены amoCRM) — только в переменных Edge Functions и в `private.amocrm_credentials`. Схема `private` не доступна через API.

### Роли и доступ (проверяется в базе, см. `0002_security_rls.sql`)

| Роль | Видит | Меняет |
|---|---|---|
| Директор | всё | всё; только он создаёт аккаунты, меняет роли, филиалы, настройки, amoCRM |
| Управляющий | назначенные филиалы | как администратор + утверждает зарплаты, бонусы, корректировки |
| Администратор | свой филиал | пробники, ученики, группы, расписание, аренда, коммунальные, расходы, страховка, черновики зарплат, штрафы |
| Отдел продаж | пробники, родители, ученики своего филиала; свои продажи | пробники, продажи, платежи |
| Тренер | свои группы, их учеников, свои смены, свои начисления | посещаемость своих занятий |

Заблокированный сотрудник не видит ничего: все проверки требуют `status = 'active'`.

### Правила целостности

- Родитель уникален по нормализованному телефону (`8 701…` = `+7 701…`). Повторная заявка привязывается к тому же родителю.
- Одна отметка посещаемости на ученика на занятии. Отменённое занятие отметок не принимает.
- Одна открытая смена на сотрудника. Ручная правка времени записывает автора.
- Зарплата = оклад (по филиалу) + занятия `scheduled`/`completed` × единая ставка (`crm_settings.lesson_rate`) + бонусы − штрафы. Посещаемость не влияет. Утверждённое начисление меняет только директор.
- Продажа хранит отдельно цену, скидку и сумму к оплате. Деньги — в `payments`; удалять платежи нельзя, только возврат.
- Платежи, выплаты и webhook-события защищены уникальным ключом от повторов.
- Каждое изменение важных таблиц пишется в `audit_logs` триггером: кто, роль, старые и новые значения, филиал, IP. Изменять и удалять журнал не может никто.
